## Regressions vs p13 (traced cause)

1. **resilience t2 lost the Team settings chip (action 1.00 → 0.40). Cause: a code change (the QU prompt navigation guard), not variance.**
   - Line-diffing the QU prompts (p13 vs p14, same turn) shows a single change, to the `navigation_target` instruction. The new text adds: "Use null for every other question: whenever the user asks for information, values or records (their balance, their email, **their team's members or roles**, an export of them) the answer is the DATA, not a page — null, even when the data concerns their own profile or team."
   - "Where can I add new members?" names "members". gpt-4o-mini now returns null on both nav turns. Both were `own_team` in p13, so this is systematic, not one-off.
   - `ActionAttacher::identityChips()` (src/Services/Actions/Attach/ActionAttacher.php:372) attaches the team chip when `mentions('Team')` in QU entity_types **or** `navigationTarget === 'own_team'`. App-nav's QU listed `["Team"]` and kept the chip. Resilience t2's QU listed `[]` (the same as p13, where `own_team` carried it) and lost it.
   - Fix direction: scope the null rule to *asking for the data* ("show/list/export members") and keep "where can I / how do I add, invite or manage members" as `own_team`. A how-to verb about a page action is navigation. Alternatively, attach the team chip when the cited doc is team-and-members.md.
2. **cold-roster `t.id = 3` hard-code is back** (p13 had `$ai_team_ids`). Generator variance; it is still scope-filtered and harmless here.
3. **Digest t2 vs the suite standard:** the new prompt makes the export sentence the opening and *mandates* a deepening closer ("Your closing offer is a deeper look you can give in this chat — never one of those buttons"). The standard says the export acknowledgment is the single closing offer, with no other deepening offer. Either update the standard to the new single-closer design, or, when `exportFormat` is set, end on the export line and drop the deepening question. Not scored down further than p13, because the double-closer is fixed.
4. **digest t1 union projection dropped** (`u.name AS union_name` was in p13's Cypher). Generator variance. The only QG prompt change is the COLUMN NAMES line. The answer was already missing the union in p13, so there is no score change. The real fix is unchanged: the composition should surface the union, and the query should project the place.
5. **rights t0 latency 81.1 s** (QU 52.4 s, file_context 24.6 s) and **resilience t1 QU 16.8 s.** No fallback or context_error was recorded, and QU tokens are unchanged (5,423 vs 5,423 input). This looks like a cold first turn or slow Qdrant/OpenAI, not code.
