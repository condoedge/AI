## Investigations

**Contribution turn (rights t2, Neo4j error).** QU got this right: `question_type: data_query`, `entity_types: [Invoice, AccountBalance, Union]`, `is_possessive: true`. So the law→data pivot routing works. The generated Cypher was valid:
```
... AND i.budget_id IS NOT NULL
AND toString(i.invoiced_at) STARTS WITH toString(date().year)
RETURN sum(toFloat(i.calc_total_amount)) ...
```
After scope injection it fails with this Neo4j error:
> `Neo.ClientError.Statement.SyntaxError` "Invalid input ')': expected 'WITH' (line 6, column 35 (offset: 301))" — `"AND toString(i.invoiced_at) STARTS) AND c.team_id IN $ai_team_ids MATCH (cu)-[:UNIT]->(ai_s0:Unit) ... MATCH (i)-[:BELONGS_TO_UNION]->(ai_s3:Union) WHERE ai_s3.team_id IN $ai_team_ids WITH toString(date().year)"`

**Root cause:** in `ai/src/Services/Security/CypherScopeAnalyzer.php`, `findAnchorIndex()` (around line 591) matches any `WITH` token at depth as a clause anchor. It does not exclude the `WITH` in the `STARTS WITH` / `ENDS WITH` string operators. The injector therefore split the predicate and spliced its scope MATCH blocks inside it.

The generator's query had two latent bugs of its own, which would have hidden behind the injector error:
- **Operator precedence:** `(unit) OR (contact) AND budget AND year` binds as `unit OR (contact AND …)`, so unit invoices from any year would have been summed.
- **Empty anchor:** it anchors on `Contact{user_id:13}` → `ContactUnit`, but Julie owns no unit. A corrected query would give a sum of 0 and a count of 0, which is honest but would still need composing as "checked: no unit/invoices billed to you".

**French-flow turn 1 (clarify misfire).** QU returned `needs_clarification: true`, `follow_up_reference: false`, `entity_types: []`, `export_format: excel` and `language: fr`, with candidate_readings ["export a specific report", "export data from a list", "export user information"]. The context shows `last_result_sample_count: 10` and `focused_entity: Team`, so the previous roster was available (gate previous_result_available passed). The "-la" pronoun plainly refers to the list just shown, so clarifying was the WRONG call; the export should have run from previous_result. On top of that, the clarifying question "What do you want to export in Excel?" is in English even though QU detected `language: fr`, so the clarify branch does not localize. The harness blamed "Clarify turn … no retrieval expected" and marked the turn gate-failed on produces_file. That attribution is correct.

## Top 5 observations
1. **Scope injector breaks `STARTS WITH` / `ENDS WITH`.** This is a new, deterministic schema/cypher defect in `CypherScopeAnalyzer::findAnchorIndex`, and it turned the suite's highest-value turn (law→data bridge) into a hard error. It will hit any generated query that filters strings by prefix or suffix. A unit test with `STARTS WITH` plus a sensitive binding is needed.
2. **The iter-12 clarify branch has a false positive plus a language bug.** It fires on an anaphoric export ("exporte-la") even with a live previous result, and it emits English on a French turn. The clarify decision should be suppressed when a previous result exists and the ask is a pronoun or export follow-up, and the question must be composed in `understanding.language`.
3. **Anchor-carry works, but only through the regex path.** The sentinel flipped 0.15 → 0.85, but QU `follow_up_reference` was false on all 14 turns. Carry currently depends on `is_follow_up_regex`, and the regex does not catch the French "exporte-la" or the pivot turns. The QU follow-up signal is effectively dead.
4. **Digest composition is still nondeterministic.** The limiter bar is fixed (failed_sources empty on back-to-back digests) and the export acknowledgment is correct. But the empty-collapse line is placed under the wrong heading (t0) or repeated three times (t2), "None pending" contradicts the listed meetings, section action links are absent in both turns, and truncation lines hang after the closing offer. Iter-12 criterion 6 (ONE empty line, deterministically) is UNMET.
5. **Data seeds have drifted with the calendar (rubric 7).** The digest t0/t1 standards assume meeting 146 (2026-07-25) is upcoming. On the run date (2026-09-29) it is past, so the fallback-to-past and "last meeting = test" are correct against the live clock, and the standards need rewriting (or the junk row deleted). Separately, the rights-duties conversation asks "my contribution" of a user who owns no unit. The seed should state that the expected answer is "no unit / nothing billed to you", with what was checked.
