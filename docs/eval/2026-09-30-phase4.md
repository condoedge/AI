## Investigation: buyer-arrears#0 `cites_document` failed

**What was retrieved.** The composition docs are the same file each time (CCQ_Co-ownership_EN.md). The number after each chunk is its own cosine score.

| Run | Chunks (doc order) | Content | Enforcement |
|---|---|---|---|
| baseline | 1075-chunk, 45, 18 | - | - |
| p1 | 1075-chunk, 1097-chunk, 18 | - | `recovered` |
| p1b | 14, 45, 1075-chunk (fusion-flattened scores 0.477 / 0.477 / 0.446) | - | `recovered` |
| **p4** | **[1] = 18 (0.503), [2] = 45 (0.483), [3] = 14 (0.496)** | [1] arts. 1060–1066: **1064 contribution, 1065 acquirer must notify within 15 days**; [2] 1093–1109: **1094 loss of vote**, 1096/1097; [3] 1047–1058 | **`failed`** |

- **Did the chunk set change?** Yes. The off-topic insurance-indemnity chunk (art. 1075, "trustee… indemnity") was replaced by chunk 18, which is **the most on-topic chunk any run has retrieved**. It sits directly before 1069.
- **Is 1.29 behind the change?** It is plausible but not provable from the trace:
  - Chunk 18 has the highest own cosine of the pool, and 1.29 made scores own-cosine instead of flat fusion ties.
  - But the 9 retrieval angles are LLM-generated per run, so the pool also varies on its own.
  - The trace logs the angles but not the per-angle hits.
- **Either way, retrieval improved rather than regressed.**
- **Near-miss:** 1069, the actual answer (the buyer is bound for dues and can request a statement within 15 days), starts **2,872 chars after 1066**. Chunk 18's window-expanded snippet is capped at ~4,506 chars and cuts off mid-1066 ("necessary period of vacan"). An article-centred or slightly larger window around the top hit would have put 1069 in the prompt. This is the Phase-7 snippet item.

**What the answer did.**
- **The prompt scaffolding is byte-identical to p1b:**
  - The system prompt is equal.
  - The user prompt differs only in the document bodies and one relevance label (48%→50%).
  - The citation instructions are unchanged: "Use citation markers [N]…", "include that file's [N] citation marker exactly as numbered above".
- **The first draft wrote the literal placeholder "([N])".** It is visible in the retry prompt, which embeds the previous draft. `CITATION_MARKER_PATTERN = /\[\d+\]/` therefore failed.
- **The retry repeated the failure.** The one-shot retry instruction again says "with [N] markers" and feeds back the draft containing "([N])". The model answered "**([N] 2)**", which still does not match, so the retry was shipped as-is with the placeholder visible to the user.
- **Enforcement had to fire in all of p1, p1b and p4:** the first draft lacks valid markers every time. The retry recovered in p1 and p1b but not in p4. **The drafting failure is systematic; the retry is a coin flip.**

**Verdict:** this is **variance exposing a latent prompt/retry design weakness, not a regression caused by the Phase 1.28–4.4 changes.** The contributing structure:
1. **Placeholder wording:** "[N]" is presented as a literal token instead of concrete numbers.
2. **Indistinguishable doc headers:** all three docs carry identical headers ("CCQ_Co-ownership_EN.md — Quebec Civil Code (relevance: 50%)"), so the model cannot tell passages apart by label. The relevance label is also the file-max, not the chunk's own score.
3. **The retry prompt re-feeds the bad token.**

**Fixes:**
- Phrase the instruction with the actual numbers ("cite as [1], [2] or [3]"), both in the file-content section and in the retry.
- Strip or neutralise "[N]" in the draft before embedding it in the retry.
- Add a deterministic post-pass: normalise "[N] k" / "([N] k)" to "[k]" and drop bare "[N]". Optionally attach a marker when a cited article number appears in exactly one retrieved doc (a structural number match, no word lists).
- Label each passage with its article range ("arts. 1060–1066") and its own score.
- Use an article-centred snippet window or neighbour-chunk expansion, so 1069 comes with chunk 18.
- If enforcement still fails, do not ship a draft that contains placeholder tokens.

## Trace usability (new format vs old)

**Everything needed to grade was present.** Several things are better than the old format:
- `prompts.composition` captures **every** composition call, including the citation-enforcement retry, which embeds the first draft. That is how the "[N]" root cause was found. The QU and query-generation prompts are captured too.
- `retrieved_chunks` now carries **`chunk_index`** and the chunk's own score. In the old format chunk_index was `None` and the score was the fusion value.
- `stages[].data` logs the file-search **angles**, the enumeration flag, the export source/rows and the branch.
- Also new: per-stage usage (tokens and calls), `branch`, `fallbacks`, `labels` / `infra` / `void`, and a fingerprint (git sha, dirty count, config sha, models).
- `response_metadata` exposes `citation_enforcement`, `truncation_honesty` and `self_reference_guard`.

**Missing or weak:**
1. **The first draft is not a first-class field.** It is only recoverable by parsing the retry's user prompt. The same applies to truncation-honesty and self-reference retries. Add `drafts[]` or `composition.attempts[]` with each text and outcome.
2. **The executed (post-tenant-scope) cypher is not shown.** Ambiguous t1's cypher has no `$ai_team_ids`, and the trace cannot prove that scoping was injected at execution. Add `cypher_executed` next to `cypher`.
3. **The `understanding` stage is not split into sub-timings.** It covers the QU LLM call, semantic entity selection / vector search and the schema build, and takes up to 20.8 s. `conversation_context` takes 8–12 s on some **turn-0s** (board t0 11.7 s, buyer t0 8.7 s) with nothing to explain it. I still need laravel.log for this, as with p1b.
4. **No per-angle retrieval hits.** Which angle found which chunk, and at what cosine? Without it, chunk-set drift between runs (buyer-arrears) cannot be attributed to 1.29 versus angle variance.
5. **Chunk scores mix two scales.** `retrieved_chunks[].score` is `chunk_relevance` for the primary and `relevance` for extras. The primary's file-max `relevance`, which drives the sort and the prompt's "relevance: 50%" label, is not exposed, so the doc order (0.503, 0.483, 0.496) is not explainable from the trace alone. `referenced_files[].relevance_score` is also the file max for every ref (tear-down: 0.4468 on both).
6. **No per-LLM-call latency.** `usage` gives tokens per stage but no milliseconds, so a composition time that includes a retry (buyer 10.8 s over 2 calls) cannot be split.
7. **`blame_reason` is always empty, and the old `scorecard` / `weakest_stage` / `blame_counts` are gone.** That is fine for agent grading, but there is no longer any automatic stage attribution.
8. **`data_sample` is still capped at 10 rows.** This is unchanged. Ambiguous t0's headline null-account row was visible, but a larger cap or a rows hash would help verify totals.
9. **Timing semantics:** `total_duration_ms` = `conversation_context` + `pipeline`. It is consistent, but undocumented.
