The code path is `AiManager::infrastructureError()` (src/Services/AiManager.php:1215) wrapping the recorded generation error, routed to `ResponseGenerator::generateErrorResponse()`.
- **The French answer is a code-level locale bug, not LLM drift.** Line 631 of `src/Services/ResponseGenerator.php` renders `__('ai.error.encountered_issue')` — Laravel's translator under the *app* locale (the string is `resources/lang/fr.json:194`) — with no reference to the question's language. Any generation failure for an English question in a French-locale host produces this exact output.
- **Most likely iter-3 cause: (F) residue — business_rule #3 rewritten to FK form.** Both broken turns route through the personal/possessive-balance generation path; this is the only iter-3 change that targets that rule, and the only conversation exercising it is the one that broke, while unit310-balance (which uses the distinct canonical "Outstanding balance of one unit" pattern) survived at 0.85. Second hypothesis, not excludable: a transient provider failure / circuit-breaker event (the known 429 signature: long generation, then error) — **not excludable because the pipeline does not persist the raw LLM generation output or the extraction/validation error**, which is itself the observability gap iteration 4 must close.
- The conversation-context mechanism also misfired independently (t0 flagged is_follow_up=true, t1 false, resolved_entity null) — pre-existing per rights-t1's identical symptom, but it removes the safety net on exactly this kind of turn.

**Other green→red flips:** rights-t1 (0.70→0.45) — citation namespace collision, attributed to (B)+context re-injection, diagnosed above. **meetings t1** is not a flip (was already red) but its −0.40 collapse is the same language-policy leak surfacing on the empty-result composition path (EN question, full FR answer, rule present in both prompts and ignored, no post-compose language gate) — two independent language escapes in one run means the policy needs enforcement in code, not prose.

# Verdict: KEEP iter-3

**KEEP — contingent on iteration 4 treating the regression as blocking.** Honest accounting: on raw numbers iter-3 is worse (mean 0.52→0.47, fails 9→11). But the losses and gains are not the same kind of thing:

- The **losses are narrow and diagnosed**: one conversation broken at a single generation code path with a named prime suspect (business_rule #3 FK residue) and a confirmed locale bug on the error path; one citation-numbering collision with an obvious fix; one language leak on the empty-result path. None indicts the retrieval lever itself — (A), (B)'s core, and (D) are clean.

Revert would trade three fixable defects for the loss of the iteration's only strategic gain. Keep, fix the regression first, and do not stack new features on the possessive-balance path until clarify-t1 is green again.
