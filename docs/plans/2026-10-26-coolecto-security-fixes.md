# Coolecto App Defects — Fix Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Fix every defect found while mapping Coolecto's data access (`ai/docs/plans/coolecto-data/access.md` §6–§7,
R-01..R-16) plus the two open items in `coolecto-progress.md` (open redirect on `redirect_to`; guest scanner
revoke/expiry). Owner: "all the errors that you found must be fixed" (2026-10-26).

**Rule for every fix:** the app's INTENT wins over what a URL happens to allow: the sidebar menu
(`app/Kompo/Menus/DashboardSidebar.php`), the help articles (`resources/ai-help/aide/**`, e.g. *compte-membres-et-roles*:
basic is read-only, scanner only scans) and the existing helpers (`currentTeamCampaigns()`, `isManager()`,
`isEditor()`, `canSeeEmails()`, `TeamPolicy`). Reuse those helpers; no new permission system. A refusal is a 403
(`abort(403)` / Kompo `authorizeBoot()` returning false) — follow how neighbouring components already refuse.

**Binding:** no git writes. TDD: a failing Feature test per defect FIRST (it reproduces the hole as the wrong role /
another team's id), then the fix, then green. Tests on the dev DB in transactions (never `RefreshDatabase`, never
`migrate`); create your own rows; `app('bootFlag')` on when instantiating Komponents (see existing tests in
`tests/Feature/Ticketing/QrCodeCheckTest.php` for the pattern). Comments 1 line. Run `php artisan test` for the touched
folders after each task and the full suite at the end; report the counts. Never print personal data.
