# Row Scope (sub-tenant data limit) Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A host can limit some users' data answers to a part of their team (CondoEdge: a resident or board member
reads only the co-ownerships they belong to, never the other syndicates their management company runs), and can
limit which entities an audience may query at all.

**Architecture:** The package's only data limit today is the team (`$ai_team_ids`, `TeamPathResolver` +
`AiSecurityService` + the executor's gate/injector). We add a second, optional limit on the SAME machinery: a host
resolver says "this user is narrowed to these ids" (`RowScopeResolverInterface`), each entity declares how it reaches
that id (`entities.X.security.row_scope_path`, same syntax as `team_path`), and for a narrowed user the security
service returns the row rule instead of the team rule — so the acceptance gate, the injector and the prompt all work
on it unchanged. A narrowed user can read only entities that have a `row_scope_path`; an audience can further list
the entities it may read (`ai.audiences.map.<key>.data_entities`). Everything fails closed.

**Tech Stack:** PHP 8.2, Laravel, Neo4j Cypher, PHPUnit (package: `vendor/bin/phpunit`; CondoEdge: `php artisan test`).

**Why (eval 2026-10-26, CondoEdge KB suites):** user 35 is a `contact` of union 8 in team 3 (12 unions). cop-04
listed maintenance of 12 co-ownerships, cop-08 "13 buildings in our syndicate", cop-15 counted every unit's keys,
cop-21 listed other unions' meetings; board members got all 305 suppliers (adm-06) and 123 bills (sui-06).

```php
declare(strict_types=1);

namespace Condoedge\Ai\Contracts;

/**
 * Narrows a user's data below their team (e.g. a resident to the co-ownerships they belong to).
 * The ids must lie inside the user's teams; the package filters on them, it does not check them.
 */
interface RowScopeResolverInterface
{
    /** @return list<int>|null null = not narrowed (team scope only); [] = no data at all. */
    public function rowScopeIds(mixed $user): ?array;
}
```

```php
<?php

declare(strict_types=1);

namespace Condoedge\Ai\Services\Security;

use Condoedge\Ai\Contracts\RowScopeResolverInterface;
use Illuminate\Support\Facades\Log;

/**
 * The host's row scope for a user (ai.security.row_scope_resolver): null when the host narrows nobody or
 * not this user, the permitted ids otherwise. A resolver that fails narrows to nothing (fail closed).
 */
final class RowScope
{
    /** @return list<int>|null */
    public static function idsFor(mixed $user): ?array
    {
        $class = config('ai.security.row_scope_resolver');
        if (!is_string($class) || $class === '') {
            return null;
        }

        try {
            $resolver = app($class);
            $ids = $resolver instanceof RowScopeResolverInterface ? $resolver->rowScopeIds($user) : [];
        } catch (\Throwable $e) {
            Log::channel(config('ai.security.log_channel', 'ai-security'))->warning('AI row scope failed', ['error' => $e->getMessage()]);

            return [];
        }

        return $ids === null ? null : array_values(array_map('intval', array_filter($ids, 'is_numeric')));
    }
}
```

```php
    /** The row rule for a narrowed user; the team ids stay bound so a generated team predicate still runs. */
    private function rowScoped($user, string $entity, string $alias, array $teamIds, array $rowIds): array
    {
        $rule = $this->pathResolver->ruleFor($entity, $alias, true);
```

```php
namespace App\Ai;

use App\Models\User;
use Condoedge\Ai\Contracts\RowScopeResolverInterface;

/** Residents and board members read the co-ownerships they belong to (as File::scopeAccessibleBy); staff read the team. */

}
```
