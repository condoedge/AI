# START HERE — condoedge/ai orientation

This is the entry point for a developer who has never seen this codebase. Read this page,
then `01-architecture-walkthrough.md` for the request lifecycle. Everything below is derived
from current source; citations are `path:line` so you can jump straight in.

## What this package is

`condoedge/ai` (namespace `Condoedge\Ai`, composer.json:2,8) is a **provider-agnostic RAG
assistant package for Kompo/Laravel host applications**. A host (CondoEdge, Sisc,
ActiviteDeFinancement) installs it, points it at its own Eloquent models, and gets a chat
assistant that answers questions about the host's data and documents. The pipeline:

- **Graph + vector retrieval** — entities live as Neo4j nodes/edges (Bolt driver,
  `src/GraphStore/BoltNeo4jStore.php`), embeddings and document chunks live in Qdrant
  (`src/VectorStore/QdrantStore.php`). All external HTTP is raw cURL; LLM and embedding
  providers (OpenAI default, Anthropic optional) sit behind `src/Contracts/LlmProviderInterface.php`
  and `EmbeddingProviderInterface.php`.
- **Query understanding** — one fast LLM call per question extracts entity types, names,
  intent, and a rewritten search query before any retrieval runs
  (`src/Services/QueryUnderstandingService.php`).
- **Security-scoped Cypher generation** — the LLM writes a read-only Cypher query; a
  structural analyzer + filter injector splice tenant (team) filters into it at execution
  time, and refuse to run anything they cannot prove scoped
  (`src/Services/Security/SecurityFilterInjector.php:36-40`).
- **Grounded responses** — the answer LLM only narrates over retrieved rows and document
  snippets; with no data and no documents the system abstains instead of improvising
  (`src/Services/AiManager.php:738-752`).
- **Approval-gated actions** — the assistant can propose host-registered actions
  (export, navigate, mutate a record). Mutating actions never execute without an explicit
  user confirmation backed by a signed single-use token
  (`src/Services/Actions/ActionDispatcher.php:11-27`).
- **Multi-surface chat UI** — Kompo components render the chat as a floating button opening
  a modal, drawer, or full screen (`src/Kompo/AiChatFloating.php`, config `ai.chat.surface`).

The system was largely AI-built; the audit tree under `docs/audit/` is the institutional
memory of *why* it has its current shape. Treat those docs as required reading for any
non-trivial change.

## Vocabulary

| Term | Meaning |
|---|---|
| **Entity catalog** | `config/entities.php`, generated by `php artisan ai:discover`. Per-model map: Neo4j label, `graph.properties`, relationships, scopes, aliases, embed fields. Every retrieval/generation stage reads it; index/ingest commands refuse to run without it (`src/Console/Commands/IndexContextCommand.php:41-46`). |
| **graph.properties** | The explicit list of columns synced onto an entity's Neo4j node. Only these sync — see sync law 1 in doc 01 (`src/Domain/ValueObjects/GraphConfig.php:20-31`, `src/Services/GraphPropertyMapper.php:29`). |
| **FK-declared edges** | Graph relationships declared in the catalog with a foreign key + target label (`src/Domain/ValueObjects/RelationshipConfig.php`). Only these outgoing edge types materialize — sync law 2 in doc 01. Polymorphic (`morphTo`) relations never become edges (`docs/audit/94c-polymorphic-edge-sync-design.md`). |
| **Scope / `cypher_pattern`** | A named, reusable filter on an entity ("pending", "active") carrying a Cypher WHERE fragment plus natural-language examples (`config/entities.php:131`). Matched semantically against the question via the `scope_examples` Qdrant collection (`src/Services/ScopeSemanticMatcher.php:27`, built by `ai:index-scopes`). |
| **user_entity_paths** | `config('ai.user_entity_paths')` — per-entity Cypher path from the authenticated user to "their" records. Empty by default; required for possessive questions ("my units") to traverse from the user (`src/Services/SemanticContextSelector.php:627-637`, `src/Services/PromptSections/CurrentUserContextSection.php:69`). |
| **QU** | Query Understanding — the pre-retrieval LLM pass producing a `QueryUnderstandingResult` (entity types, person names, intent, question type, rewritten search query, corpus translations) stamped on `PipelineContext->qu`. Gated by `AI_QUERY_UNDERSTANDING_ENABLED` (config/ai.php:795). |
| **Abstention** | The no-grounding safety behavior: empty query data + no referenced files means the turn is flagged degraded and the response comes from `ResponseGenerator::generateEmptyResponse` ("no results found"), never a confident invented answer (`src/Services/Chat/UseCases/AskQuestionUseCase.php:176-178`, `src/Services/ResponseGenerator.php:322`). |
| **Action / ActionKind** | A host capability implementing `src/Contracts/AiActionInterface.php`, registered in config. `handle()` returns data + an `ActionKind` intent (`Element`, `Table`, `Export`, `Pending`, `Error`) — never a UI element (`src/Services/Actions/ActionKind.php`). |
| **Approval token** | The HMAC-signed, TTL-bound (`ai.actions.token_ttl`, default 900s, config/ai.php:1223), user-bound, single-use `PendingActionToken` minted at render time for a mutating action. Only `ActionDispatcher::approve()` — after re-verifying all of that — calls `handle()`. |
| **Native tool channel** | When `ai.actions.native_tools` is on (default OFF, config/ai.php:1224) and the response LLM implements `src/Contracts/ToolCallingLlmInterface.php`, actions are offered as native provider tools via a bounded loop (`src/Services/Actions/ToolLoopRunner.php`); otherwise they ride the markdown `action://` link grammar. One decision point: `src/Services/Actions/ActionToolGate.php`. |
| **page_context** | A soft prior describing the page/record the chat was opened from, passed by the host when mounting `AiChatFloating` (e.g. `['entity_type' => 'Union', 'entity_id' => ...]`). It biases entity selection and adds one retrieval angle; it never hard-filters (`src/Services/AiManager.php:459-464`, `src/Services/ContextRetriever.php:275-278`). |
| **Identity** | `ai.identity` (assistant name, persona, language policy, config/ai.php:57-66) rendered by `src/Services/AssistantIdentity.php` + `src/Services/ResponseSections/IdentitySection.php` so the assistant stays white-labeled and never self-identifies its model provider. |

## The five invariants — nobody may break these

1. **Security fails closed.** No permissions metadata, no auth adapter, no provable scope
   placement — all mean *deny*, never *allow*. `ai.security.on_permission_unexistent`
   defaults to `'deny'` (config/ai.php:269); `NullAuthAdapter` returns zero teams so every
   secured query is denied (`src/Auth/NullAuthAdapter.php:23-54`); `SecurityFilterInjector`
   returns `null` on any residual ambiguity and the executor refuses the query
   (`src/Services/Security/SecurityFilterInjector.php:36-40`).
2. **Mutating actions never execute before approval — on any channel.** `dispatch()` defers
   every `mutates()` action behind a signed `PendingActionToken`; only
   `ActionDispatcher::approve()` (HMAC → TTL → user binding → fresh `authorize()` →
   single-use nonce) ever calls `handle()` (`src/Services/Actions/ActionDispatcher.php:11-27`,
   `docs/audit/94b-native-tool-calling-design.md` §2.1).
3. **Single execution path / no dead code.** One canonical path per behavior; both action
   transports converge on `ActionInvocation` → `ActionDispatcher`; duplicate or unreached
   code gets deleted, not kept "just in case". Enforcement doc:
   `docs/audit/93-dead-code-and-duplication.md`.
4. **Tests run per-file, with this exact command** — the full-suite run segfaults
   (`docs/audit/EXECUTION-SUMMARY.md:7`):

   ```bash
   php -d opcache.enable_cli=0 vendor/bin/phpunit <file> --no-coverage
   ```

5. **Comments state present facts only.** Explain *why*, never narrate versions
   ("previously/now"), never leave speculative placeholders
   (`docs/audit/10-of-10-acceptance-rubric.md:24`, `docs/audit/99-roadmap.md:21`).
